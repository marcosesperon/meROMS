# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

meROMS is a desktop ROM manager for EmulationStation gamelist.xml files. Built with Tauri v2, React 19, TypeScript, and Tailwind CSS. It lets users browse ROM systems, view/edit game metadata, manage media, and add/remove game entries. It supports two folder structures through **profiles** — Classic EmulationStation and ES-DE — and can migrate a library between them. It also scrapes metadata and media from online databases and offers maintenance tools (duplicates, unused media, media normalizer, ROM renaming with cleanup rules, backups, multi-disc playlists, collections). The UI is available in English, Spanish, French, Portuguese, Italian and German.

## Features

- **Profiles** — several saved libraries (ROM folder + structure: Classic or ES-DE), switched in Settings → Profiles; ES-DE paths read from `es_settings.xml`; a profile whose folder doesn't exist now (SD card / USB disk unplugged) is "not available": `profiles::profiles_available` (ROM folder and, in ES-DE, the ES-DE folder are dirs), the store's `profileUnavailable` (`loadSystems` checks first and doesn't scan; `setProfileUnavailable` = `goHome` + no systems), `App` re-checks every `PROFILE_CHECK_MS` (3 s: loads the systems when it appears, back to the start screen when it goes; the ROM watcher is off meanwhile), `WelcomeScreen` notice, `ProfilesTab` dims it with "not connected" and doesn't activate it (it can still be edited or deleted)
- **Browse & edit** — LaunchBox-style layout: compact systems sidebar, cover grid (default) or table, fixed read-only game info panel on the right (hero, media gallery, details; system summary when nothing is selected), centered modal editor (media | data columns) opened with Edit / double click; dark warm theme with violet accent
- **Media** — unified naming `<ES-DE folder>/<ROM name>.<ext>` in both structures; preview and set images/videos per game
- **Scraping** — media types also include back cover (`box-2D-back` → `backcovers/`, `boxback`), physical media (`support-2D` → `physicalmedia/`, `cartridge`) and the PDF manual (`manuel` → `manuals/`, `manual`), «don't touch» by default; ScreenScraper's media extension comes from its `format` (`find_media`), not the `mediaJeu.php` URL; LaunchBox maps `Box - Back`, `Cart - Front`/`Disc` (only after re-downloading its database); TheGamesDB, the back boxart; ScreenScraper, then (arcade) ArcadeItalia → LaunchBox or (rest) LaunchBox → TheGamesDB (`source_order`/`scrape_one`: the first that finds the game wins; only available sources), single game or whole system with progress; one game = manual search (`ScrapeSearchModal`: text + optional all systems, results from both sources in one list, the ROM's MD5 match first; picking one runs `apply_scrape`), also offered for the games Scrape All didn't find; meROMS' ScreenScraper developer credentials can be built in at compile time (`src-tauri/build.rs`: env `MEROMS_SS_DEVID`/`MEROMS_SS_DEVPASSWORD` or the git-ignored `src-tauri/screenscraper.env`; CI secrets `SS_DEVID`/`SS_DEVPASSWORD`), so users only enter their account; what it may update is a `ScrapePolicy` per data field and media type (`overwrite` / `if_empty` — media: only if the file is missing, not even requested — / `keep`), saved as `scrape_fields` (derived from the old `ss_media_types` until saved) and overridable per "Scrape All" run; region order (names, dates, media) and language order (texts) are `ss_regions`/`ss_languages` (defaults from the app language; `get_scrape_order`)
- **Gamelist generation** — build a gamelist.xml from the ROM files in a system folder; manage `<folder>` entries
- **Media types** — detect covers/screenshots saved the other way round (by image shape), swap two media types for a whole system, or re-type one media file in the editor ("This is...")
- **DAT files** — per system (MAME `-listxml`, Logiqx/clrmamepro XML, No-Intro Parent-Clone; a compact JSON copy is kept in the app data dir `dats/`): missing games, ROM files not in the DAT, clone/BIOS tags + "Hide clones" filter, names from the DAT description; matching by content (CRC32) after "Check by content", else by file name; "DAT name" source in Rename
- **Bulk edit** — "Select" button in `Header` (`SelectButton`, shows the count) or the "Multi-select" switch in the filter bar; Cmd/Ctrl+click turns it on and marks, Shift+click marks the range from the last marked in `visibleOrder` (`clickGame`/`clickKeys` in `utils/gameClick.ts`, grid and table); `BulkEditPanel` `MarkedActions`: Scrape (N) (Scrape All with `ToolRequest.gamePaths`), Put in order (N) (`OrderModal` `initialScope` marked), Versions (N) (`onlyPaths`), Remove (N) (set aside per My collection, else trash); the old filter-bar switch: clicks mark games and the right panel becomes `BulkEditPanel` (common fields with a "change" checkbox, flags yes/no/keep, find & replace with case/regex and preview, "Rename (N)..." opens Rename with the marked games — the old "Article of the name" section lives there now); one gamelist save

## Architecture

### Structures and the layout layer

Every path decision goes through `layout::Layout` (`Classic` | `Esde`). Never build gamelist/media/backup/collection paths by hand in commands:

| | Classic | ES-DE |
|---|---|---|
| gamelist | `<ROMs>/<sys>/gamelist.xml` | `<ES-DE>/gamelists/<sys>/gamelist.xml` |
| media | `<ROMs>/<sys>/<folder>/<ROM stem>.<ext>` | `<media>/<sys>/<folder>/<ROM stem>.<ext>` |
| media paths in XML | yes | no (found by ROM name) |
| backups | next to the gamelist in `.backups/` (max 20) | same |
| collections | `<ROMs>/<sys>/custom-*.cfg`, `./x` entries | `<ES-DE>/collections/custom-*.cfg`, `%ROMPATH%/<sys>/x` entries (merged) |

- Commands still receive the system's ROM folder (`system_path`); `commands::system_context(&app, &system_path)` returns the active profile's `Layout` + `SystemRef`. No active profile ⇒ Classic.
- Always read/write gamelists through `commands::gamelist::read_gamelist` / `write_gamelist`. In ES-DE, `read_gamelist` fills media fields in memory with absolute paths (`media::hydrate_gamelist`) and `write_gamelist` strips them, so the UI works the same for both structures.
- The parser preserves unknown `<game>` children/attributes and unknown root elements (e.g. ES-DE `<alternativeEmulator>`).

### Rust Backend (`src-tauri/src/`)

- `lib.rs` — App builder: registers plugins (dialog, fs, opener), the custom `media://` URI protocol (serves local images/videos from absolute paths with the right MIME type) and all Tauri commands
- `main.rs` — Desktop entry point
- `layout/` — `Layout`, `SystemRef`, `EsdePaths`, media stem rules, `is_own_folder` (ES-DE's own folders are never systems when ES-DE lives inside the ROM folder); `esde_settings.rs` reads `ROMDirectory`/`MediaDirectory`/`LegacyGamelistFileLocation` from `es_settings.xml`; portable ES-DE: picking the executable folder uses its `ES-DE` data subfolder (returned as `esde_home`), `%ESPATH%` = folder with `ES-DE.exe`/`portable.txt`, default ROMs `<ESPATH>/ROMs`
- `rom_hash.rs` — ROM CRC32: `archive_entries`/`single_archive_entry` read `.zip` (`zip`, no decompressors) and `.7z` (`sevenz-rust2`) indexes without extracting; `file_crc` streams loose files; `CrcCache` (`crc_cache.json` in the app data dir, by path + size + mtime). ScreenScraper (`ss_game_by_rom`) sends the inner file's `crc`/`romtaille`/`romnom` for single-file archives instead of the archive's MD5
- `media.rs` — Single table of media kinds (ES-DE folder ↔ gamelist field ↔ scraper types), `MediaIndex` (one directory walk per system), hydration, scraped-media targets, rename/move/copy helpers (never overwrite)
- `rename_rules/` — Regex cleanup rules engine (`CompiledRules`) and built-in `default_rules.json` (from ES-DE-Roms-Renamer, MIT; "(Disc x) → .partx" disabled)
- `models/` — Data structs (all serde Serialize/Deserialize):
  - `game.rs`, `folder.rs`, `gamelist.rs`, `provider.rs` — `Game`, `Folder`, `GameList`, `Provider` (gamelist.xml content)

### Data Flow

1. User creates/selects a profile in Settings → Profiles (ES-DE folder auto-fills ROM/media folders) → saved to app data dir
2. `scan_systems` reads the active profile's ROM folder subdirectories → Sidebar populates
3. User clicks system → `load_gamelist` reads the gamelist where the layout keeps it (ES-DE: media filled by ROM name) → table/grid renders (filtered via `useFilteredGames`)
4. User clicks game → detail panel opens with form + media previews (served through `media://`)
5. Edits save via `save_gamelist` → previous gamelist.xml copied to `.backups/` → XML written back (ES-DE: without media paths)
6. Scraping: media saved with unified naming; `scrape_system` emits `scrape-progress` events consumed by `ScrapeProgressModal`
7. Migration: `plan_migration` (preview) → `run_migration` (progress events) → optionally create & activate the destination profile

## Frontend ↔ Backend IPC

- Frontend calls Rust: `import { invoke } from "@tauri-apps/api/core"` → `invoke("command_name", { args })` (camelCase args map to snake_case Rust params)
- Rust defines commands: `#[tauri::command] fn command_name(arg: Type) -> ReturnType`; long-running work should be `async` + `tauri::async_runtime::spawn_blocking`. A plain `#[tauri::command]` runs on the main thread and freezes the window, so every command that touches the disk is `#[tauri::command(async)]` (thread pool); such a sync body runs on a worker of Tauri's async runtime (not `spawn_blocking`), so `lib.rs` `run` installs its own tokio runtime with `RUNTIME_WORKERS` (64) workers via `tauri::async_runtime::set` — with one worker per core, a few long commands made every other call, even native dialogs, wait minutes
- Long processes report progress and can be cancelled: the command takes `task: Option<String>` and uses `commands::progress::Progress` (`step(phase, n, total, item)` → `task-progress` event, at most every 50 ms; `phase(phase)` without a count; analyses `check()?` → error `"cancelled"`; changes `if progress.cancelled() { break }` and then save what was done; `cancel_task(task)`; `Progress::none()` for internal calls and tests, `Progress::for_task` in tests). Frontend: `hooks/useTask` (`run((task) => cmd(..., task))` returns `null` when an analysis was cancelled; `progress`, `running`, `cancelling`, `cancel`, `wasCancelled`; `newTaskId`/`subscribeTask` outside components) + `common/TaskProgress` (phase label `task.phase.<key>`, bar or moving bar when total is 0, file name, Cancel)
- Commands must be registered in `lib.rs`: `.invoke_handler(tauri::generate_handler![...])`
- Tauri plugin permissions: `src-tauri/capabilities/default.json`

## Adding Tauri Plugins

```bash
pnpm add @tauri-apps/plugin-<name>
cargo add tauri-plugin-<name> --manifest-path src-tauri/Cargo.toml
```
Register in `lib.rs` with `.plugin(tauri_plugin_<name>::init())` and add permissions to `capabilities/default.json`.
