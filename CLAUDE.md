# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

meROMS is a desktop ROM manager for EmulationStation gamelist.xml files. Built with Tauri v2, React 19, TypeScript, and Tailwind CSS. It lets users browse ROM systems, view/edit game metadata, manage media, and add/remove game entries. It supports two folder structures through **profiles** — Classic EmulationStation and ES-DE — and can migrate a library between them. It also scrapes metadata and media from online databases and offers maintenance tools (duplicates, unused media, media normalizer, ROM renaming with cleanup rules, backups, multi-disc playlists, collections). The UI is available in English and Spanish.

## Features

- **Profiles** — several saved libraries (ROM folder + structure: Classic or ES-DE), switched in Settings → Profiles; ES-DE paths read from `es_settings.xml`
- **Browse & edit** — LaunchBox-style layout: compact systems sidebar, cover grid (default) or table, fixed read-only game info panel on the right (hero, media gallery, details; system summary when nothing is selected), centered modal editor (media | data columns) opened with Edit / double click; dark warm theme with violet accent
- **Media** — unified naming `<ES-DE folder>/<ROM name>.<ext>` in both structures; preview and set images/videos per game
- **Scraping** — ScreenScraper, then (arcade) ArcadeItalia → LaunchBox or (rest) LaunchBox → TheGamesDB (`source_order`/`scrape_one`: the first that finds the game wins; only available sources), single game or whole system with progress; one game = manual search (`ScrapeSearchModal`: text + optional all systems, results from both sources in one list, the ROM's MD5 match first; picking one runs `apply_scrape`), also offered for the games Scrape All didn't find; meROMS' ScreenScraper developer credentials can be built in at compile time (`src-tauri/build.rs`: env `MEROMS_SS_DEVID`/`MEROMS_SS_DEVPASSWORD` or the git-ignored `src-tauri/screenscraper.env`; CI secrets `SS_DEVID`/`SS_DEVPASSWORD`), so users only enter their account; what it may update is a `ScrapePolicy` per data field and media type (`overwrite` / `if_empty` — media: only if the file is missing, not even requested — / `keep`), saved as `scrape_fields` (derived from the old `ss_media_types` until saved) and overridable per "Scrape All" run; region order (names, dates, media) and language order (texts) are `ss_regions`/`ss_languages` (defaults from the app language; `get_scrape_order`)
- **Gamelist generation** — build a gamelist.xml from the ROM files in a system folder; manage `<folder>` entries
- **Media types** — detect covers/screenshots saved the other way round (by image shape), swap two media types for a whole system, or re-type one media file in the editor ("This is...")
- **DAT files** — per system (MAME `-listxml`, Logiqx/clrmamepro XML, No-Intro Parent-Clone; a compact JSON copy is kept in the app data dir `dats/`): missing games, ROM files not in the DAT, clone/BIOS tags + "Hide clones" filter, names from the DAT description; matching by content (CRC32) after "Check by content", else by file name; "DAT name" source in Rename
- **Bulk edit** — "Multi-select" switch in the filter bar: clicks mark games and the right panel becomes `BulkEditPanel` (common fields with a "change" checkbox, flags yes/no/keep, find & replace with case/regex and preview); one gamelist save
- **Games without ROM** — gamelist entries whose ROM file/folder is gone: marked in grid/table, "No ROM (N)" button to remove them and send their media to the trash
- **New ROMs** — ROM files in the system folder (and subfolders) that the gamelist doesn't have: add them with editable names (proposed with the cleanup rules) and optionally scrape just those
- **Cleanup** — find unused media files and duplicate games, then delete them; placeholders (the same file in ≥ 5 different games) are trashed and learned into a blocklist the scraper skips
- **Media normalizer** — Classic: move legacy-named media (suffixes, `images/`…) to the unified naming (optional before migrating: the migrator does it on the fly); ES-DE: recover Classic-structure media left in the ROM folder into the ES-DE media folder
- **Migration** — Classic ↔ ES-DE, copy or move; gamelists, media and collections (ROMs never touched); systems found in the other structure are offered for migration when entering a profile and per system
- **Per-game tools** — Rename, Normalize media and Clean up leftover media from the game detail panel
- **Rename** — batch-rename ROM files from the gamelist title or with regex cleanup rules (ES-DE-Roms-Renamer style); updates media, gamelist, collections and `.m3u`
- **Backups** — automatic gamelist.xml backup before every save (Scrape All: one, before the run); list/restore/delete
- **Collections** — detect multi-disc games and generate `.m3u` playlists; generate custom collections
- **Export** — export a gamelist; export/import app settings
- **Windows installers** — `bundle.windows.nsis` (`installerIcon` = `icons/icon.ico`, `headerImage` 150×57, `sidebarImage` 164×314) and `bundle.windows.wix` (`bannerPath` 493×58, `dialogImagePath` 493×312) in `tauri.conf.json`; 24-bit BMPs in `src-tauri/icons/installer/`, composed from `icons/source/installer.html` (how to regenerate them is in its header). The `.msi` file itself always shows Windows' MSI icon
- **Self-update** — `tauri-plugin-updater` + `tauri-plugin-process`; `useUpdateStore` (check at start and daily unless `check_updates` is false, download/install with progress, relaunch), `UpdateBanner` + `UpdateModal` (release notes); signed with the updater key (secrets `TAURI_SIGNING_PRIVATE_KEY`/`_PASSWORD`, pubkey in `tauri.conf.json`); `latest.json` is built when a Release is published (`.github/workflows/updater.yml`), not by the build jobs
- **About & donation** — Settings → About (version, author, GitHub / website / Buy Me a Coffee); a "meROMS is free" prompt at most once a week (`donation_prompt_at`; the first launch only starts the count); links in `src/utils/links.ts`

## Architecture

### Structures and the layout layer

Every path decision goes through `layout::Layout` (`Classic` | `Esde`). Never build gamelist/media/backup/collection paths by hand in commands:

| | Classic | ES-DE |
|---|---|---|
| gamelist | `<ROMs>/<sys>/gamelist.xml` | `<ES-DE>/gamelists/<sys>/gamelist.xml` |
| media | `<ROMs>/<sys>/<folder>/<ROM stem>.<ext>` | `<media>/<sys>/<folder>/<ROM stem>.<ext>` |
| media paths in XML | yes | no (found by ROM name) |
| backups | next to the gamelist in `.backups/` (max 20) | same |
| collections | `<ROMs>/<sys>/custom-*.cfg`, `./x` entries | `<ES-DE>/collections/custom-*.cfg`, `%ROMPATH%/<sys>/x` entries (merged) |

- Commands still receive the system's ROM folder (`system_path`); `commands::system_context(&app, &system_path)` returns the active profile's `Layout` + `SystemRef`. No active profile ⇒ Classic.
- Always read/write gamelists through `commands::gamelist::read_gamelist` / `write_gamelist`. In ES-DE, `read_gamelist` fills media fields in memory with absolute paths (`media::hydrate_gamelist`) and `write_gamelist` strips them, so the UI works the same for both structures.
- The parser preserves unknown `<game>` children/attributes and unknown root elements (e.g. ES-DE `<alternativeEmulator>`).

### Rust Backend (`src-tauri/src/`)

- `lib.rs` — App builder: registers plugins (dialog, fs, opener), the custom `media://` URI protocol (serves local images/videos from absolute paths with the right MIME type) and all Tauri commands
- `main.rs` — Desktop entry point
- `layout/` — `Layout`, `SystemRef`, `EsdePaths`, media stem rules, `is_own_folder` (ES-DE's own folders are never systems when ES-DE lives inside the ROM folder); `esde_settings.rs` reads `ROMDirectory`/`MediaDirectory`/`LegacyGamelistFileLocation` from `es_settings.xml`; portable ES-DE: picking the executable folder uses its `ES-DE` data subfolder (returned as `esde_home`), `%ESPATH%` = folder with `ES-DE.exe`/`portable.txt`, default ROMs `<ESPATH>/ROMs`
- `rom_hash.rs` — ROM CRC32: `archive_entries`/`single_archive_entry` read `.zip` (`zip`, no decompressors) and `.7z` (`sevenz-rust2`) indexes without extracting; `file_crc` streams loose files; `CrcCache` (`crc_cache.json` in the app data dir, by path + size + mtime). ScreenScraper (`ss_game_by_rom`) sends the inner file's `crc`/`romtaille`/`romnom` for single-file archives instead of the archive's MD5
- `media.rs` — Single table of media kinds (ES-DE folder ↔ gamelist field ↔ scraper types), `MediaIndex` (one directory walk per system), hydration, scraped-media targets, rename/move/copy helpers (never overwrite)
- `rename_rules/` — Regex cleanup rules engine (`CompiledRules`) and built-in `default_rules.json` (from ES-DE-Roms-Renamer, MIT; "(Disc x) → .partx" disabled)
- `models/` — Data structs (all serde Serialize/Deserialize):
  - `game.rs`, `folder.rs`, `gamelist.rs`, `provider.rs` — `Game`, `Folder`, `GameList`, `Provider` (gamelist.xml content)
  - `profile.rs` — `Profile`, `StructureKind` (`classic` | `esde`)
  - `settings.rs` — `AppSettings` (profiles + active profile, scraper credentials, media field mapping, rename rules…), `MediaPathConfig` (camelCase on the wire), `SystemConfig`; `migrate_legacy()` turns the old `rom_root_path` into a default Classic profile
  - `system.rs` — `SystemInfo` plus static per-system tables: ROM extensions, full names, ScreenScraper/scraping platform IDs
  - `scraper.rs` — `ScrapeResult`, `ScrapeProgress`
- `parser/mod.rs` — XML parsing via `quick-xml`: `parse_gamelist()` and `serialize_gamelist()`
- `commands/` — Tauri command handlers (most take `app: AppHandle`, injected by Tauri):
  - `settings.rs` — `get_settings` (migrates legacy settings), `save_settings`, `export_settings`, `import_settings`
  - `profiles.rs` — `detect_esde_paths`, `detect_pending_structure` (systems of the active profile whose data is only in the other structure + the source profile to migrate from: same-folder Classic, saved ES-DE profiles or `~/ES-DE`)
  - `systems.rs` — `scan_systems` (reads ROM root subdirs, checks for the gamelist where the layout keeps it), `system_locations` (ROM folder, gamelist path + exists, media base + existing media folders with file counts — legacy ones too in Classic —, backups, collections; shown in the system summary)
  - `gamelist.rs` — `load_gamelist`, `save_gamelist`, `add_game`, `remove_game`, `generate_gamelist`, `add_folder`, `remove_folder`; `read_gamelist`/`write_gamelist`/`write_gamelist_with_original`/`write_gamelist_no_backup` helpers; `set_sort` (from `gamelist_sort` in Settings, set when settings are read or saved) makes every write sort games/folders by name or path (every write goes through a `gamelist.xml.tmp` renamed over the real file, so a crash never leaves half a gamelist)
  - `images.rs` — `set_game_media` (copies a picked file with unified naming), `scan_game_media`, `switch_image_type` (Classic only)
  - `scraper.rs` — `search_scrape` (manual search: ScreenScraper `jeuInfos.php` by MD5 + `jeuRecherche.php` by text, TheGamesDB `ByGameName` in parallel; `ScrapeSearch` = `ScrapeCandidate` cards + per-source `errors`; ScreenScraper cover URLs carry the credentials, so they stay in a static map and `scrape_thumbnail` returns each as a data: URI, asked one at a time), `apply_scrape` (picked result by id — `jeuInfos.php?gameid=` / `Games/ByGameID` — through the same policy code; not saved), `scrape_game` (automatic, ScreenScraper if configured, else TheGamesDB; no longer used by the UI), `scrape_system` (per game: ScreenScraper, then TheGamesDB; optional `game_paths` subset; emits `scrape-progress` with `game_path`; one backup before starting, then `write_gamelist_no_backup` every `SAVE_EVERY` (10) games and at the end; `cancel_scrape` sets a flag checked before each game; returns `{ stopped }`; keeps a resume reminder — `resume: true` continues it with its own games and rules), `scraper_status` (built-in developer credentials? ScreenScraper/TheGamesDB usable? — the UI uses it, never the raw settings; `AppSettings::ss_dev_credentials` = user's if both set, else built-in)

  - `scrape_resume.rs` — `scrape_resume.json` in the app data dir: per gamelist path, the games a Scrape All still had to do, its rules, total and start date (written at start and at every save, removed when the run ends); `get_scrape_resume` (shown in `ScrapeAllModal` as Continue / Start over)
  - `scrape_common.rs` — shared by the newer sources: `ScrapedData` + `apply_data` (policy per field), `fetch_media` (policy, placeholder check, extension from URL or content, unified naming), `normalize_title`, `es_date`

  - `scraper_adb.rs` — ArcadeItalia (`service_scraper.php?ajax=query_mame&game_name=`), arcade systems only (`is_arcade_system`, mirrored in `src/utils/arcade.ts`): data (history without its first line and technical sections as description), ss/sstitle/marquee, flyer as box-2D, shortplay video

  - `placeholders.rs` — media placeholders: `find_placeholder_media` (same size, then MD5, in ≥ `PLACEHOLDER_MIN_GAMES` (5) distinct games; MD5 only for sizes that reach it), blocklist `media_placeholders.json` in the app data dir (path set in `lib.rs` `setup` via `init`, kept in memory), `learn_placeholders`, `placeholder_count`, `forget_placeholders`, `is_placeholder(bytes)` checked by `download_media` (ScreenScraper) and `download_image` (TheGamesDB) before writing — a placeholder counts as not downloaded

  - `dat.rs` — `set_system_dat`/`clear_system_dat`, `dat_report` (missing, `unknown_files` via `new_roms::rom_files`, clone/BIOS `marks`, `names` for unnamed games, `content_matched`; matching by CRC from the cache first — `pick_by_crc`, ties broken by name — then by ROM file stem; the report never computes CRCs), `dat_compute_crcs` ("Check by content": fills the CRC cache for the system's ROMs, emits `dat-crc-progress`), `names_by_content` (for Rename's `dat` source); `DatGame::crcs` only for games with ≤ `MAX_CRC_ROMS` (4) ROMs — arcade stays matched by name; `DatSummary::has_crcs` false for DATs saved by older versions (pick them again)
  - `duplicates.rs` — `find_duplicates` (groups with a reason code `screenscraper_id`/`hash`/`similar_name` + `detail`), `remove_games_with_files` (removes the entries and sends ROM + all its media to the trash; Classic keeps media used by games that stay; `dry_run` lists the files; a game whose ROM can't be trashed stays)
  - `normalize.rs` — `plan_media_normalization` (optional `game_path`), `apply_media_normalization` (both structures; ES-DE moves Classic leftovers from the ROM folder into the media folder and doesn't rewrite the gamelist; a file found by name goes to one destination only)
  - `migrate.rs` — `plan_migration`, `run_migration` (take the source `Profile` itself — it may be a detected, unsaved one — and an optional `systems` subset; Classic → ES-DE renames legacy-named media on the fly using `normalize::plan`; same code path with `dry_run`; async + `spawn_blocking`; emits `migration-progress`)
  - `bios.rs` — BIOS check: `bios_download` (libretro `System.dat`, CC BY-SA, downloaded — not bundled — and kept parsed in `bios_list.json`), `parse_system_dat` (clrmamepro: `comment` = section, `rom ( name size md5 … )`, quoted names with subfolders), `libretro_section` (system folder → section), `bios_dir` (profile `bios_dir` or the usual `<ROMs>/../bios`, ES-DE also `<ES-DE>/../bios`), `check` (one walk of the BIOS folder; exact path or same name in any subfolder; size then MD5 → ok/missing/mismatch), `check_bios` (`BiosModal` and the "BIOS: N of M" line in the system summary), `suggested_bios_dir` (placeholder in Profiles)
  - `undo.rs` — undo the last rename/move/normalize/swap (in memory, only the last one): `media.rs` keeps a per-thread journal (`journal_begin`/`journal_take`; `move_file`, the direct `fs::rename`s of rename and `rename_rom_media`, and shared-media copies in move record themselves); each op records `UndoOp` (files + `GameChange` before/after per game via `changes_by_path`/`changes_same_paths` + `RefUndo` for collections/.m3u); `undo_last` moves files back in reverse (skipping if moved since or the original place is taken), restores each game's path and only media fields still holding the op's value, moves entries back between systems, and re-runs `update_references`/`update_collections` reversed; `undo_status` for Tools > "Undo: …". UI: `utils/undo.ts` (`reportWithUndo` = result dialog with "Undo", `runUndo`), `undoInfo`/`refreshUndo` in the store
  - `export_device.rs` — "Export to device": destination with the profile's structure (Classic `<dest>/<sys>`; ES-DE `<dest>/ROMs/<sys>` + `<dest>/ES-DE/{gamelists,downloaded_media}`), `plan_export` (games filter all/favorites/visible, ROM + `companion_files` or folder-ROM files, chosen media folders; copy if missing, other size or newer — 2 s margin for FAT32; leftovers only inside the chosen systems' folders, skipping gamelist.xml and dot folders), `run_export` (`export-progress`, `cancel_export`; writes the destination gamelists with only the exported games — Classic media fields only for copied types — keeping the device's higher play stats; deletes leftovers for real, no trash), `pull_changes`/`apply_pull` (favourite/hidden if different, playcount/gametime/lastplayed if higher there); `export_targets` in Settings (last 5, managed by `ExportDeviceModal`)
  - `chd.rs` — "Convert to CHD": `chdman` is not bundled (GPL); `find_chdman` (setting `chdman_path`, else PATH, else usual dirs — Homebrew, /usr/bin, `C:\\Program Files\\MAME`…; no console window on Windows), `chd_status` (path + version); `supports_chd` = the system's extension table (`models/system.rs`) has `.chd`; `list_chd_candidates` (gamelist entries with a `.cue`/`.gdi`/`.iso` ROM or an `.m3u` of those — `.chd` discs left alone, anything else ⇒ not offered —; size with `companion_files`; `blocked: "exists"` if a `.chd` with that name exists); `convert_to_chd` (`createcd`, `createdvd` for PS2/PSP ISOs, to `<stem>.meroms-tmp.chd`, then `verify`; all discs fine ⇒ renamed to `.chd`, else every CHD of that game removed; percent parsed from chdman's `\r` lines → `chd-progress`; `cancel_chd` kills the running chdman; game and disc entries → `.chd` path, `rename::update_references` for `.m3u` lines and collections, media untouched (same stem); gamelist written after each game, first time with backup; originals: trash / keep / subfolder keeping relative paths). UI: `ChdModal` (install help + "Choose chdman…"), path also in Settings → General
  - `compare.rs` — "Compare with another folder": the library vs a folder with the profile's structure (`export_device::dest_layout`), systems of both sides; games matched by path without `./` (only entries whose ROM exists), files = `export_device::rom_files` (ROM + `companion_files`, or a folder-ROM's files); `compare_folders` (`only_here` / `only_there` / `different` = other files or sizes, with `check_crc` also same-size files with another CRC via `CrcCache`; `same` count; emits `compare-progress`), `apply_compare` (actions `{system, game_path, to: here|there}`: copies ROM files + all media to the unified name, entry added/replaced with all its data — Classic media fields rewritten —; what the receiving side had for that game is removed first: library → trash, other folder → deleted; a failed copy removes that game's copied files; library gamelist written with backup, the other without; `cancel_compare` between games); last folder in `compare_dest`. UI: `CompareModal`
  - `best_version.rs` — "Best version" (1G1R): `parse_tags` (No-Intro/Redump tags of the file name: regions → Settings codes, a European country also counts as `eu`; languages `Xx`/`Xx-YY`; Rev N/A/vX.Y; Beta/Proto/Demo/Sample/Pirate/Hack/Unl and `[b]` = unwanted; `[!]` verified), groups by `dat::version_groups` (cloneof or own name; content match first) else by the normalized base name, score = (unwanted, best region position, best language position — implied from the region when untagged —, newest revision, verified), ties → shortest name; `best_versions` returns groups of 2+ with `reason`. `BestVersionModal` applies: hide (`hidden`), move (`move_games` to a subfolder) or trash (`remove_games_with_files`)
  - `translate.rs` — `translate_texts` (DeepL: `api-free` for `:fx` keys, batches of 50, `null` when DeepL detects the target language; key `deepl_apikey` in Settings); used by the editor's "Translate" (fills the form) and `BulkEditPanel`'s translate section (saves)
  - `move_games.rs` — "Move to...": `list_subfolders` (ROM subfolders, skipping media/hidden/ES-DE folders and folder-games), `move_games` (to another system and/or subfolder: ROM + `companion_files` — .cue FILE lines, .gdi tracks, .m3u entries and their .cue bins — keeping relative positions, media via `MediaIndex`/`current_file` to the unified name in the destination, gamelist entry moved with all its data (Classic: media fields rewritten; a media file shared with another game is copied), both gamelists written with backup; collections: ES-DE lines rewritten, Classic moved from the source system's custom-X.cfg to the destination's); a game whose destination files exist is skipped whole, nothing is overwritten; a failed ROM move undoes that game's files
  - `rename.rs` — `list_rename_candidates` (each entry also carries `tracks`: .cue/.gdi tracks named after the game — `track_renames`, via `move_games::sheet_names` — that are renamed along with it, rewriting the sheet with `rewrite_sheet` and journaling it as `Journaled::Rewritten` for Undo; a clashing track makes the entry `exists`; source `title` | `rules` | `dat` — DAT name for ROMs recognised by content, extension kept —, optional `game_path`, flags `duplicate`/`exists` conflicts), `check_rename_target` (a hand-typed name: `invalid`/`exists`), `rename_roms` (returns renamed/skipped; updates collections and `.m3u`)
  - `rules.rs` — `get_default_rename_rules`, `test_rename_rules`, `import_rename_rules`, `export_rename_rules`
  - `backup.rs` — `list_backups`, `restore_backup`, `delete_backup`
  - `export.rs` — `export_gamelist`
  - `collections.rs` — `detect_multidisc_games`, `generate_m3u_playlists`, `generate_collection`

### Data Flow

1. User creates/selects a profile in Settings → Profiles (ES-DE folder auto-fills ROM/media folders) → saved to app data dir
2. `scan_systems` reads the active profile's ROM folder subdirectories → Sidebar populates
3. User clicks system → `load_gamelist` reads the gamelist where the layout keeps it (ES-DE: media filled by ROM name) → table/grid renders (filtered via `useFilteredGames`)
4. User clicks game → detail panel opens with form + media previews (served through `media://`)
5. Edits save via `save_gamelist` → previous gamelist.xml copied to `.backups/` → XML written back (ES-DE: without media paths)
6. Scraping: media saved with unified naming; `scrape_system` emits `scrape-progress` events consumed by `ScrapeProgressModal`
7. Migration: `plan_migration` (preview) → `run_migration` (progress events) → optionally create & activate the destination profile

## Frontend ↔ Backend IPC

- Frontend calls Rust: `import { invoke } from "@tauri-apps/api/core"` → `invoke("command_name", { args })` (camelCase args map to snake_case Rust params)
- Rust defines commands: `#[tauri::command] fn command_name(arg: Type) -> ReturnType`; long-running work should be `async` + `tauri::async_runtime::spawn_blocking`
- Commands must be registered in `lib.rs`: `.invoke_handler(tauri::generate_handler![...])`
- Tauri plugin permissions: `src-tauri/capabilities/default.json`

## Key Dependencies

- **Rust**: quick-xml (XML serde), regex (rename rules), reqwest + tokio (scraper HTTP), md-5 (ROM hashing for ScreenScraper), zip + sevenz-rust2 + crc32fast (ROM CRCs, `rom_hash.rs`), chrono (backup timestamps), percent-encoding/urlencoding, tauri-plugin-dialog, tauri-plugin-fs, tauri-plugin-opener; dev: tempfile
- **JS**: zustand (state + i18n), @tanstack/react-table (table view), tailwindcss, @tauri-apps/plugin-dialog, @tauri-apps/plugin-fs, @tauri-apps/plugin-opener

```bash

```
